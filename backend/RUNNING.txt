Customer Reply Assistant: backend APIs
=====================================

Status: All four endpoints in openapi.yaml are implemented: draft generation,
reply saving, history listing, and record details. The frontend is served by the
same FastAPI process at http://127.0.0.1:8000/. No separate frontend build is needed.
Drafts are not saved automatically, sent, or generated by an external model.

Use Python 3.12; runtime dependencies were upgraded following a security scan. Run these commands from the project directory:

    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements-dev.txt
    python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000

Open http://127.0.0.1:8000/docs to try the endpoint:
1. Expand POST /api/drafts.
2. Select Try it out.
3. Enter {"question": "What is your return policy?"}.
4. Select Execute to see the draft and FAQ source.

Try {"question": "Please reset my password."} for the no-match response.
FAQ data is loaded at startup; restart the server after changing faqs.json.

The tracked openapi.yaml defines the target contract. FastAPI's /openapi.json
and /docs describe all four implemented endpoints.

Run all unit and API integration tests:

    python -m unittest discover -s backend/tests -v

Run API integration tests only:

    python -m unittest discover -s backend/tests/integration -v

These tests make in-process HTTP requests using TestClient; no running server,
external API credentials, or internet connection is needed after installation.
API responses are checked against schemas in the tracked openapi.yaml.

Saving a reviewed reply
----------------------
In /docs, use POST /api/replies with this example body:

    {"question": "What is your return policy?", "reply": "Hello, unused items in original packaging may be requested for return within 30 days of delivery, excluding final-sale items. A reviewer will confirm eligibility.", "faq_id": "faq-101"}

The endpoint returns 201 with the saved record, generated ID, and UTC timestamp.
For a manual reply with no source, send "faq_id": null explicitly.
Unknown FAQ IDs and invalid fields return 422 without inserting a record.
The backend accepts the reviewer's chosen existing source; it does not verify
that the edited reply is factually supported by that source.
Each successful POST creates a new record, including repeated submissions.

Database configuration
----------------------
By default, replies are stored in backend/data/replies.db, relative to the source
file rather than the shell directory. The folder and table are created at startup.
The database persists across restarts and is excluded from Git.

To choose another location, set DB_PATH before launching:

    export DB_PATH=/absolute/path/to/demo-replies.db
    python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000

An absolute path is recommended; a relative DB_PATH resolves from the shell's
working directory. Environment variables are read directly; .env files are not
loaded automatically. Use separate paths for development and deployment.
Tests create temporary databases and never use the default database.
Deployment will require a persistent disk or volume for this SQLite file.
FAQ content remains in faqs.json; only saved replies are stored in SQLite.
The initial table is created non-destructively with CREATE TABLE IF NOT EXISTS;
future schema changes will require a migration rather than deleting user data.

Viewing history
---------------
Use GET /api/replies in /docs to list saved replies, newest first. limit defaults
to 20 (allowed: 1-100); offset defaults to 0 (must be nonnegative).
For example: GET /api/replies?limit=10&offset=0
The response includes items and total; total counts all saved records, not just
this page. Empty history or an offset beyond the end returns an empty items list.
Records are sorted by created_at descending, then ID descending for timestamp ties.

Use GET /api/replies/{id} with a returned record ID to see the complete record.
Unknown positive IDs return 404 with {"detail": "Reply not found."}.
Invalid pagination values or record IDs return 422.

Frontend usage and tests
-----------------------
Open http://127.0.0.1:8000/ after starting the server.
Enter a question (or select an example), generate a draft, review the source,
edit the response, and select Save reply. Select a history item to view it.
Unmatched questions allow a manual reply. Changing a question requires a new
lookup before saving. Saving an edited reply creates a new record rather than
updating the previous record. Identical repeated clicks are blocked in the UI.
History loads five records per page. Failed saves preserve the current text.
If a save response is lost, check history before retrying to avoid duplication.

All backend calls are centralized in frontend/api.js. UI state is managed in
frontend/state.js; frontend/app.js connects that state to the page.
Dynamic questions, answers, and sources use textContent rather than HTML.

To run frontend unit tests (Node.js 18 or newer, no npm install required):

    cd frontend
    node --test tests/*.test.js

These tests cover save eligibility, stale questions, manual replies, duplicate
prevention, request formatting, and request failures.

Store demo data
---------------
The active knowledge base describes Northstar Demo Store, a fictional online
shop. Return windows, prices, and processing times are sample rules only.
The assistant cannot issue refunds, change orders, or retrieve tracking status.
New store FAQs use IDs faq-101 through faq-112. Earlier market-data FAQs used
faq-001 through faq-012; those IDs are not reused, so old saved source references
are not silently reassigned to unrelated store policies. Existing saved replies
remain in history. Restart the server or rebuild Docker to load the new FAQs.

Hosted PostgreSQL
-----------------
DATABASE_URL selects PostgreSQL; DB_PATH remains the local SQLite option.
Render requires DATABASE_URL to prevent accidental ephemeral storage.
See docs/deployment.md for free hosting and PostgreSQL test instructions.
